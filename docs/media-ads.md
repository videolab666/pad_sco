# Медиа-плейлист (реклама) на табло

Фото и видео, которые клуб загружает заранее и которые автоматически показываются
на экранах табло, когда корт простаивает. Управление — страница **/settings**,
вкладка «Настройка рекламы» (пароль тот же, что на главной: `SETTINGS_PASSWORD`,
по умолчанию `111`; сессия — httpOnly-cookie на 30 дней).

## Из чего состоит

| Часть | Где | Что делает |
|---|---|---|
| Медиатека | `media_items` + Storage bucket `media` | файлы клуба, квота хранилища |
| Плейлисты | `media_playlists` + `media_playlist_items` | порядок показа + «виртуальный дубликат» |
| Состояние кортов | `media_state` | играется/не играется, источник, книга корта |
| Настройки клуба | `club_settings` (`key='media'`) | квота + триггеры (+ переопределения по кортам) |

Файлы грузятся **напрямую в Supabase Storage** по presigned-URL
(`POST /api/media/upload-url` → `PUT` → `POST /api/media/confirm`), поэтому
большие видео не проходят через тело Next.js-функций. Чтение — публичные URL
(bucket `media` public), писать может только сервер (service role).

## Триггеры показа (`media-core.ts → evaluateMediaState`)

Автоматическое включение (все пороги в минутах, 0 = выключено):

- **afterCompletedMin** — матч на корте завершён N минут назад (один показ на матч);
- **noScoreMin** — в живом матче N минут не было очков;
- **noMatchMin** — на корте N минут нет матча;
- приоритет: завершённый матч > простой > нет матча.

Остановка:

- **stopOnAnyScore** — любое очко гасит показ (клиент реагирует мгновенно, без
  ожидания сервера);
- **stopOnNewMatch** — на корт назначили новый матч;
- **maxSessionMin** — жёсткий потолок длительности сессии;
- **loopsLimit** — лимит полных циклов плейлиста;
- **cooldownAfterStopMin** — после остановки авто-показ не раньше чем через N минут;
- принудительная сессия (ручная/команда) с `forcedUntil` после его истечения
  продолжает жить только если сработал обычный триггер.

`manualOnly` отключает всю автоматику. Всё то же самое можно переопределить
**для конкретного корта** (per-court overrides). Расписание — общеклубовое,
per-court не переопределяется.

### Расписание (ночные окна)

Список окон в настройках триггеров (`schedule`), каждое: режим, дни (Пн–Вс,
пусто = все дни), время «с–до» в минутах от полуночи (`22:00→08:00` — окно
через полночь; равные значения = круглосуточно) и общий часовой пояс
(`scheduleTzOffsetMin`, минут от UTC; `null` = по часам сервера — важно
указать смещение, если продакшен в UTC, а клуб нет):

- **«Показывать всегда»** — в окно реклама крутится, пока на корте нет ЖИВОГО
  матча (ночью без матчей и с завершённым матчем; лимит «один показ на
  завершённый матч» не действует — экран не гаснет). Если матч живой —
  работают обычные триггеры (простой и т.д.), расписание с ним не спорит;
- **«Запретить автопоказ»** — в окне автотриггеры выключены (прайм-тайм),
  играющая автосессия гасится; ручной/remote-показ работает всегда.

Источник показа в этом случае — `schedule` (виден в UI управления по кортам
и в JSON state). Кулдаун после остановки действует и на расписание — для
непрерывного ночного показа поставьте «Пауза после остановки» = 0.

Кто решает: каждый экран раз в ~10 секунд дергает публичный
`GET /api/media/state?court=N` — сервер сам запускает редьюсер и персистит
переходы, экранам не нужно ничего писать. Плюс realtime-подписка на
`media_state` для мгновенной реакции на ручной старт/стоп.

## «Виртуальный дубликат» (bumper)

Клубное видео-заставка вставляется между рекламными роликами:

- `afterEveryN` — после каждого N-го файла плейлиста;
- `minIntervalSec` — но не чаще, чем раз в M секунд (по сумме длительностей);
- файл заставки берётся из медиатеки, сам в плейлист не входит.

## Вертикальные видео на горизонтальном экране

Видео с `height > width` показывается `object-contain` по центру, а фоном —
та же картинка/видео, размытая и растянутая (`blur-3xl + scale-1.4`). В
медиатеке (/settings) для вертикального видео можно выбрать **фон-фото** —
любую картинку из библиотеки (`PATCH /api/media/items/[id]` с `bgItemId`;
`null` — снова размытие самим видео). При удалении фото-фона ссылки
автоматически снимаются у всех видео, которые его использовали.

## API

Все мутации требуют авторизации: cookie сессии `/settings` **или** `X-API-Key`
(`SCOREBOARD_API_KEY`).

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/settings/login` | вход (`{password}`), GET — статус, DELETE — выход |
| GET | `/api/media/state?court=N` | **публичный**: что играть на корте (запускает авто-триггеры) |
| GET | `/api/media/state` | **публичный**: сводка по всем кортам |
| POST | `/api/media/state` | ручной показ/стоп (см. ниже) |
| GET | `/api/media/library` | медиатека + плейлисты + квота (для /settings) |
| POST | `/api/media/upload-url` | квота-пречек + presigned URL |
| POST | `/api/media/confirm` | зафиксировать загруженный файл |
| PATCH/DELETE | `/api/media/items/[id]` | переименовать/вкл/выкл/удалить |
| GET/POST | `/api/media/playlists` | список / создать |
| PATCH/DELETE | `/api/media/playlists/[id]` | имя, дефолт, bumper, состав |
| GET/PATCH | `/api/media/settings` | квота + триггеры |

### Удалённая команда «покажи рекламу на корте»

```bash
curl -X POST https://<host>/api/media/state \
  -H "X-API-Key: $SCOREBOARD_API_KEY" -H "Content-Type: application/json" \
  -d '{"court":3,"action":"show","source":"remote","forcedUntilMin":30}'
# остановить
curl -X POST https://<host>/api/media/state \
  -H "X-API-Key: $SCOREBOARD_API_KEY" -H "Content-Type: application/json" \
  -d '{"court":3,"action":"hide"}'
```

Сценарий клуба: игрок ушёл, матч не доигран, корт простаивает — команда включает
рекламу на 30 минут; любое новое очко (если `stopOnAnyScore` включён) или новый
матч погасит показ сами.

## Проверка

- `npx vitest run test/media-core.test.ts` — 32 юнит-теста логики
  (включая расписание и окна);
- `node scripts/media-e2e-driver.mjs` — 38 e2e-проверок против запущенного
  сервера (логин, квота, реальная загрузка байтов в Storage, плейлисты, bumper,
  триггеры, ночное окно always/deny, фон-фото, state, очистка за собой);
- миграция: `node scripts/apply-media-migration.mjs` (идемпотентна).

## Ограничения / следующие фазы

- Видео играют **без звука** — браузеры не дают autoplay со звуком без жеста
  пользователя.
- Квота и RLS: медиа-таблицы читаются публично через API сервером (service
  role); прямой доступ к таблицам из браузера не нужен.
- Google Drive-синхронизация — отложена (оговорено с заказчиком).
