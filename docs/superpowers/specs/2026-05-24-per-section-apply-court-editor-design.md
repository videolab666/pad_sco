# Per-section Apply + редактор корта во время матча

**Дата:** 2026-05-24
**Файлы:** `components/match-settings.tsx`, `lib/translations.ts`
**Статус:** approved

## Контекст

Сейчас на странице матча:
1. Номер корта (`match.courtNumber`) показан Badge'ем, **редактировать нельзя** — только при создании матча.
2. Все остальные настройки матча (правила, счёт сетов) применяются мгновенно через `applySettingsAuto()`/`updateSetScore()` → `updateMatch()`. Пользователь не видит явного подтверждения сохранения.

Запрос: разрешить менять/добавлять корт во время матча, и иметь кнопки «Применить» по группам настроек, чтобы пользователь точно знал, что изменения внесены.

## Решение

В `MatchSettings` вводится **draft-модель** для трёх логических групп:

- **Корт** (новый блок вверху панели): Select 1–10 или «без корта».
- **Правила матча** (все 6 существующих visual-блоков обёрнуты в один Card): Sets / Final-set Tiebreak / Scoring System / Games per set / Tiebreak / Additional.
- **Редактирование счёта**: таблица +/– по сетам.

Каждая группа имеет:
- локальный draft, который пишется при изменении контрола (вместо немедленного `updateMatch`);
- статус-бар внизу: `✓ Сохранено в HH:MM` / `• Не сохранено` + Apply / `⏳ Сохраняется...` / `❌ Ошибка` + Повторить;
- кнопку «Применить», которая коммитит весь draft группы за один `updateMatch()`.

Существующий поток `requestRuleChange()` → `classifyRuleChange()` → AlertDialog «Применить сейчас / Перезапустить сет / Отмена» **сохраняется** для группы Правил: открывается после клика Apply, если новые правила трогают живой счёт.

## Edge cases

- **Внешний sync `match`**: чистый draft пере-синхронизируется из match; грязный draft остаётся, индикатор показывает «несинхронизировано». Revision check внутри `updateMatch` ловит реальный конфликт.
- **`match.isCompleted`**: все контролы + Apply disabled (как сейчас).
- **Корт = null**: разрешено («без корта»). Supabase `court_number` nullable.

## Что НЕ меняется

- Тапы по счёту (A+/B+, undo) на скорборде — мгновенные.
- `updateMatch()`, revision/optimistic concurrency, real-time sync — не трогаем.
- `pendingRuleChange` AlertDialog — остаётся, просто срабатывает раз на Apply.

## Тесты

- `test/match-settings-draft.test.tsx`: контрол меняет draft, не `match`; Apply вызывает `updateMatch` один раз; внешний update сбрасывает только чистый draft.

- `components/match-settings.tsx`: ~300 строк изменений.
- Новый внутренний компонент `SectionApplyBar` (~50 строк).
- `lib/translations.ts`: ~10 новых ключей (RU/EN).
