# Автоматические проверки

Единая команда проверки всего кода:

```bash
npm run check
```

Она по очереди выполняет:

1. **`tsc --noEmit`** — проверка типов всего проекта;
2. **`vitest run --coverage`** — все тесты + покрытие кода с порогами;
3. пишет полный лог в `logs/check-<дата>.log` и печатает сводку;
4. завершается с ненулевым кодом при любой ошибке (готово для CI / git-хука).

## Команды

| Команда | Что делает |
|---------|------------|
| `npm run check` | Полная быстрая проверка: типы + unit/компонентные тесты + покрытие + лог |
| `npm test` | Только unit/компонентные тесты (быстро) |
| `npm run test:watch` | Тесты в watch-режиме — перезапуск при сохранении файла |
| `npm run test:coverage` | Тесты + отчёт покрытия (`logs/coverage/index.html`) |
| `npm run typecheck` | Только проверка типов |
| `npm run e2e` | E2E + API в реальном браузере (Playwright, отдельно — медленнее) |
| `npm run e2e:report` | Открыть HTML-отчёт последнего E2E-прогона |

## Три слоя проверок

1. **Unit-тесты** (`test/*.test.ts`) — чистая логика `lib/` через Vitest.
2. **Компонентные тесты** (`test/components/*.test.tsx`) — React-компоненты
   рендерятся в jsdom, клики эмулируются. Среда задаётся строкой
   `// @vitest-environment jsdom` в начале файла. Без сервера и Supabase.
3. **E2E + API** (`e2e/*.spec.ts`) — Playwright поднимает реальный `next dev`
   и Chromium: прокликивание страниц + проверка JSON-эндпоинтов. Логи —
   trace/скриншоты/видео при падении в `logs/playwright-results`,
   HTML-отчёт в `logs/playwright-report`.

Слои 1–2 входят в `npm run check`. Слой 3 (E2E) — отдельной командой
`npm run e2e`, так как он медленнее и требует запуска сервера.

## Структура тестов

- `test/**/*.test.ts` — Vitest подхватывает автоматически. **Чтобы добавить
  проверки нового вида спорта — просто создайте файл `test/<sport>.test.ts`.**
  Никакой регистрации не нужно.
- `test/match-view.test.ts` — **эталонный пример** unit-теста. Копируйте форму.
- `test/components/*.test.tsx` — компонентные тесты (jsdom). Примеры —
  `test/components/score-board.test.tsx`, `score-controls.test.tsx`.
- `test/use-match.test.tsx` — тест хука `useMatch` (`renderHook`, jsdom).
- `test/*-regression.ts` — старые автономные скрипты на `node:assert`. Их
  подключают тонкие обёртки `test/*.test.ts`. Запускаются и отдельно через
  `npx tsx test/<файл>.ts`.
- `e2e/*.spec.ts` — Playwright-сценарии: `smoke.spec.ts` (прокликивание
  страниц), `api-smoke.spec.ts` (JSON-эндпоинты). Добавить сценарий — создать
  файл `e2e/<имя>.spec.ts`.

## Соглашение (как писать новый тест)

```ts
import { describe, it, expect } from "vitest"
import { computeSomething } from "../lib/my-sport"

// фабрика фикстур — переопределяемая в каждом тесте
function makeMatch(overrides = {}) {
  return { /* ...минимальный валидный матч... */, ...overrides }
}

describe("my-sport: computeSomething", () => {
  it("описывает ожидаемое поведение одним предложением", () => {
    expect(computeSomething(makeMatch())).toBe(42)
  })
})
```

Правила:
- один `describe` на модуль/функцию, один `it` на одно поведение;
- название `it` — предложение, описывающее ожидание;
- чистую логику держим в `lib/` — тогда она попадает в охват покрытия.

## Покрытие кода

Охват покрытия задан в `vitest.config.ts` (`coverage.include`) — пока это
чистые модули логики в `lib/`. Пороги (`coverage.thresholds`): проверка падает,
если покрытие опускается ниже. При добавлении новых модулей в `lib/`:

1. добавьте файл в `coverage.include`;
2. напишите для него `test/<module>.test.ts`;
3. при росте покрытия поднимайте пороги.

HTML-отчёт: `logs/coverage/index.html` (видно непокрытые строки/функции).

## Проверка ключей перевода

`test/translations-keys.test.ts` сканирует весь UI-код, находит вызовы
`t("...")` и проверяет, что каждый ключ существует в `lib/translations.ts`.
Это ловит опечатки и неверные неймспейсы (`t()` принимает любую строку —
типы такое не ловят, ошибка видна только в рантайме).

Известные на момент внедрения пропуски занесены в `KNOWN_MISSING` внутри
теста — это технический долг. Тест падает на **новых** пропусках и на
**устаревших** записях `KNOWN_MISSING` (ключ починили — удалите его из списка).
Список только сокращается, не растёт.
